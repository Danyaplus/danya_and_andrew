# Kodumi Games — рефакторинг 28 октября 2026 года

## Что входит в этот ПОЛНЫЙ архив

Основой служит только `danya_and_andrew-main (8).zip` + последний патч витрины
от 28.10.2026. Никакие более старые архивы не использованы.

### Реализовано в коде

- Все 50 игр переведены на `React.lazy` + `Suspense`: загрузка компонентов по требованию,
  список и поиск игр остаются доступными сразу.
- У всех 47 повторяющих функцию получения гостевого имени компонентов одна
  реализация `frontend/src/lib/playerName.js`, старый ключ имени сохранён.
- Добавлены реальные API и сохранение языка в Supabase; включена проверка значений.
- `VITE_SERVER_URL` действительно учитывается фронтендом; предусмотрен адрес
  localhost для разработки, прежний адрес для существующего production-билда.
- Полная пагинация при старте загрузки пользователей, сессий, друзей и заявок,
  быстрый поиск по Map для id пользователя, логина и токена сессии,
  вместо молчаливой остановки на лимите Supabase в 1000 строк.
- Асинхронный `scrypt` для регистрации, входа и смены пароля без замены хешей.
- Единый JSON-каталог магазина для Node и React, единый JSON-список платных
  титулов; отдельный магазин титулов удалён.
- В редакторе витрины обновление с сервера не сбрасывает незавершённый выбор.
- Реакции чата переключаются в атомарной транзакции PostgreSQL (`FOR UPDATE`).
- Непрочитанные диалоги и последнее сообщение вычисляются базой по всей истории,
  а не по первым 1000 сообщений. Для этого добавлены индексы и SQL-функция.
- Неполная загрузка серверной игры теперь явно останавливает запуск сервера,
  а не скрывает ошибку.
- Для настроек профиля добавлены ограничения частоты изменений.
- Удалены 47 пустых `sd.js` и ненужный `ProfileTitlesShop.jsx`.
- Новое название в пакетах / workflow, тесты каталогов и структуры.
- Меньше принудительно скачиваемых изображений на начальном экране.

### Что не следует выдавать за готовое

Следующие пункты первоначального аудита **не реализованы до конца**: перенос
старых Base64-аватаров в Supabase Storage, транзакционное объединение всех
начислений XP/монет/событий, вынос всех 50 игровых механик в общие модули,
распределённый сервер матчей, полное разбиение `server.js` и `AccountModal.jsx`,
снятие сотен `!important` в CSS, избавление от всего `DomTranslator`,
обновление всех старых localStorage-ключей и создание полного схемного бэкапа
всех исторических SQL-функций. Эти задачи нельзя честно считать законченными
без проверки действующей базы, тестовых матчей и визуальных тестов мобильной
версии. Они намеренно не затронуты, чтобы не испортить текущие механики.

## Важная последовательность установки

1. Создайте **резервную копию Supabase** (не только ZIP исходников!).
2. Сохраните текущий сайт и `.env` на хостинге, убедитесь, что доступен откат.
3. В Supabase SQL Editor запустите `supabase/profile-showcase-titles.sql`, если
   ранее не запускали, затем **`supabase/2026-10-28-safe-refactor.sql`**.
   `chat-upgrade.sql` должен быть применён ранее.
4. Обновите код бэкенда; переменные Supabase и CLIENT_ORIGIN оставьте прежними.
5. Для фронтенда установите `VITE_SERVER_URL` на **текущий** адрес бэкенда.
   Не оставляйте старый адрес Render, если переехали на украинский хостинг.
6. Выполните `npm install`, `npm test`, `npm run build` на компьютере/CI
   с доступным npm-реестром, затем разверните сайт.
7. Обязательно проверьте: логин/смену языка/аватар/друзей/чат/реакции/магазин/
   получение медали/цвет титула/переподключение к матчу/все основные типы игр.
8. При ошибке сначала посмотрите консоль Node и SQL Editor. Не выполняйте
   случайные `DROP TABLE` или очистку пользовательских данных.

- Синтаксис JSX прошёл отдельный анализ парсером TypeScript.
- `npm test` — тесты целостности успешно прошли.
- Полную сборку Vite не удалось запустить: недоступны необходимые пакеты в
  offline npm cache. Без реальной Supabase нельзя подтвердить выполнение SQL.
- Проверки браузера/мобильного устройства/реальных матчей не выполнялись.

Рекомендация: **не выкладывать напрямую всем игрокам**, пока не выполнены
проверки из пунктов 6–7. Код проекта в полном архиве рассчитан на staged rollout.
